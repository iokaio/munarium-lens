# Serving and diagnosis

The reference backend loads no model assets and reports
`"retrieval_model": false`. Use it for the synthetic probes in the
[local walkthrough](../guides/local-development.md). The opt-in Qwen3
backend loads verified model bundles. Deployment qualification is pending.

## Service authentication

The proposed service profile uses a separate pool bearer for each endpoint.
Mount the secret read-only and point `LENS_SERVICE_BEARER_FILE` at it. Store
32 randomly generated bytes as 64 lowercase hexadecimal characters. A final
LF or CRLF is accepted. Configure Server's inference provider
`credentialRef` with the same value. Place the service on a private network
and terminate TLS before traffic crosses that network boundary.

`/v1/models`, `/readyz`, `/v1/embeddings` and `/v1/rerank` require that
bearer when configured. `/healthz` returns only process liveness. Configure
readiness probes to obtain the bearer from the secret. A missing or invalid
credential returns HTTP 401 and a Bearer challenge. A bad secret file fails
startup, including when the unauthenticated development override is set.

For rotation, coordinate Lens replacement workers and the Server credential,
then rerun Server's discovery and inference probe. Server continues to
authorize the user, collection and tenant placement before dispatch.

## Model-backed serving

1. Obtain the approved image by digest and each verified profile manifest with
   its expected digest. Place verified assets in an operator-managed
   directory outside the repository and mount it read-only at a
   deployment-specified path such as `/models`.
2. Configure stage-to-manifest bindings and limits from the exact qualification
   receipt. Use approved device and runtime versions, service credentials and
   private connectivity. Disable serving-time egress and model downloads,
   or, with the opt-in [startup fetch](../../README.md#fetching-at-startup),
   allow HTTPS egress only to the documented Hugging Face and GitHub download
   hosts and mount a writable cache volume.
3. Check liveness, then require readiness evidence for the intended stage,
   exact served identity and successful synthetic profile probe before adding
   the worker to routing. `GET /readyz` returns HTTP 200 only when every
   configured stage passed its startup probe, and lists each ready stage's
   model, backend, dimensions, manifest digest and limits. Check Server's actual enrollment probe from the
   authenticated deployment before sending collection data.
4. On bad manifest or missing file, check the configured mount and recorded
   expected digest. Correct the import or mount and restart with the same
   approved identity. On load or probe failure, compare runtime/device and
   pinned dimensions or output shape to the receipt. Leave the worker out
   of rotation until it passes.
5. For transport or timeout failures, check service auth, routing, queue
   age, worker health and Server's remaining deadline and attempt record.
   Do not replay a submitted request from the gateway. Keep diagnostics free
   of credentials, payload text and source paths.

For replica changes or rollback use the [scaling runbook](scaling.md).
The [artifact design](../design/artifacts-and-serving.md) defines the
verification and readiness prerequisites.
